# Netegram Native

Тот же клиент, что и [Netegram](https://github.com/weholy/netegram) — тот же интерфейс, тот же код экранов, — но без MTProto и без серверов Telegram. Свой сервер, свой протокол, свой вход.

Название рабочее: репозиторий переименовать в GitHub можно в любой момент, ничего в коде от имени не зависит.

## Что уже сделано

- **`server/`** — рабочий бэкенд (Node.js + TypeScript): регистрация/вход, чаты один-на-один, сообщения в реальном времени по WebSocket, история сообщений. Проверено вручную end-to-end: вход → создание чата → отправка сообщения → доставка второй стороне в реальном времени → сохранение в базе.
- **`client/`** — исходник Netegram как есть, один в один. Пока всё ещё говорит по MTProto с серверами Telegram — замена сети описана ниже, это следующий и самый большой этап.

## Вход через Telegram-бота

Без своего SMS-провайдера: код на вход присылает Telegram-бот, которого вы заводите сами.

1. Пользователь открывает бота в Telegram, жмёт `/start`.
2. Бот просит поделиться номером телефона (кнопка "Отправить номер" — Telegram позволяет через неё передать только номер своего же аккаунта, поэтому это надёжная привязка).
3. Сервер запоминает номер и chat_id переписки с ботом.
4. При входе в приложении пользователь вводит тот же номер → сервер шлёт код через бота → пользователь вводит код в приложении.

Это не MTProto — обычный, документированный Telegram Bot API (HTTPS-запросы к `api.telegram.org/bot<token>/...`), используемый ровно для одной вещи — доставки кода. Учётные записи, чаты и сообщения полностью свои, на своём сервере.

## Как запустить сервер

```sh
cd server
npm install
cp .env.example .env
npm run dev
```

Без `TELEGRAM_BOT_TOKEN` в `.env` сервер поднимется и будет работать (регистрация напрямую в базе для тестов, чаты, WebSocket), но не сможет разослать код входа — при попытке `/auth/request-code` вернёт `502 delivery_failed` вместо того, чтобы соврать об успехе.

**Получить токен:** в Telegram написать [@BotFather](https://t.me/BotFather) → `/newbot` → вставить токен в `.env`.

База — SQLite-файл (`server/data/netegram.db` по умолчанию), создаётся сама при первом запуске. Для прод-нагрузки план — перейти на Postgres; слой доступа к данным уже собран так, чтобы это было заменой одного файла (`src/db/db.ts`), а не переписыванием запросов по всему проекту.

### API v1

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/auth/request-code` | `{phone}` → шлёт код через бота |
| POST | `/auth/verify` | `{phone, code}` → `{token, user}` |
| GET | `/chats` | список чатов с превью последнего сообщения |
| POST | `/chats/direct` | `{phone}` → id чата один-на-один (создаёт, если его ещё нет) |
| GET | `/chats/:id/messages` | последние 50 сообщений |
| WS | `/ws?token=...` | `{type:"send", chatId, text}` → рассылается всем участникам чата как `{type:"message", ...}` |

## План замены сети в клиенте

Это самая большая оставшаяся часть. Делать по одному вертикальному срезу за раз, с проверкой на каждом шаге, — а не одним большим патчем: клиент компилируется только в облачной сборке (~50 минут за попытку), и вслепую резать 1642 сгенерированные функции TL-протокола и 755 файлов, завязанных на схему Postbox, — верный способ потратить много часов на один незамеченный тайпо.

Порядок:

1. **Авторизация.** Заменить экран ввода номера/SMS-кода (`AuthorizationUI`) так, чтобы он звал новый `/auth/request-code` и `/auth/verify` вместо `auth.sendCode`/`auth.signIn` в MTProto. Самый маленький и самый безопасный первый шаг — почти не трогает остальной клиент.
2. **Транспорт.** `MtProtoKit`'s `Network`/`Connection` — на клиент нового WebSocket-протокола. Здесь `TelegramApi`'s 1642 TL-функций перестают быть нужны почти целиком; останется реализовать реальный список используемых операций (отправить сообщение, получить историю, список чатов) под новый протокол.
3. **Синхронизация.** `Postbox`'s `AccountStateManager` — сейчас обрабатывает `pts`/`qts`-последовательности Telegram; заменить на приём `{type:"message"}` по WebSocket и запись напрямую в локальную базу клиента.
4. **Дальше по важности:** медиа (фото/файлы), группы, звонки — каждое отдельным срезом поверх готовых первых трёх.

Функции этого форка, завязанные конкретно на протокол Telegram (анти-удаление через перехват `messages.setTyping`, фейк-активность через `acquireLocalInputActivity` и так далее — см. [netegram](https://github.com/weholy/netegram)), в этой ветке теряют смысл или требуют отдельного переосмысления под собственный протокол; в объём этого этапа не входят.
